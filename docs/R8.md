# R8 в release-сборке

В `app` включено `release.optimization.enable = true`: AGP 9.3.1 выполняет
минификацию, обфускацию, оптимизацию кода и ресурсов. `keepRules.includeDefault = true`
подключает `proguard-android-optimize.txt`. Используется стандартный R8 full mode.
Debug-сборка остаётся без минификации.

AGP объединяет стандартные правила Android, consumer rules зависимостей,
правила из manifest/ресурсов и `app/src/main/keepRules/*.keep`. Расширение `.keep`
и этот каталог — API используемого AGP; отдельный `proguard-rules.pro` не нужен.

## Проверенные зависимости

Проверены не только рекомендации разработчиков, но и правила внутри фактически
разрешённых AAR/JAR из `releaseRuntimeClasspath`. Транзитивные версии могут
отличаться от исходных запросов в version catalog.

| Зависимость | Правила и решение |
| --- | --- |
| AndroidX, Compose, Navigation 2.10.0 | Consumer rules, включая `@Keep`, и генерируемые Android entry points. Дополнительных keep для всех Activity/ViewModel/Composable нет. |
| kotlinx.serialization 1.11.0 | JAR содержит common/R8 rules для сериализаторов. DTO и типизированные navigation routes используют `@Serializable`; именованных companion objects нет, дополнительные правила из документации не требуются. |
| Ktor 3.5.1 | `ktor-utils-jvm` содержит `META-INF/proguard/ktor.pro`: volatile-поля и discovery engine. В приложении также явно выбран `HttpClient(OkHttp)`. |
| kotlinx.coroutines 1.11.0 | Core/Android JAR содержат R8 rules для atomic-полей и Android dispatcher. Дублировать их не нужно. |
| OkHttp 5.3.2 / Okio 3.17.0 | Android AAR OkHttp содержит правила для необязательных TLS providers. Для текущего использования Okio отдельных правил не требуется. |
| MapLibre OpenGL 13.4.1, GeoJSON 6.0.1, Gson 2.10.1 | `proguard.txt` MapLibre сохраняет JNI-зависимые типы, GeoJSON и Gson JSON tree. Native callbacks также используют `@Keep`. Gson применяется библиотекой; приложение сериализует DTO через kotlinx.serialization. Правила MapLibre не дублируются и не расширяются до всего SDK/Gson. |
| Koin 4.1.1 | Эта версия ещё не содержит consumer rules более новых Koin. Используемые DSL-фабрики и ViewModel создаются прямыми вызовами; рефлексивного поиска конструкторов нет. Koin FragmentFactory/WorkManager не используются. Дополнительных правил не требуется. |
| Orbit 10.0.0 | В используемых core/viewmodel/compose нет собственных consumer rules; контейнеры и состояния доступны по прямым ссылкам. SavedStateHandle хранит обычные значения, пользовательских Parcelable/Java Serializable payloads нет. |
| Timber 5.0.1 / SLF4J 2.0.18 | Timber содержит consumer rule для annotations. Release-логирование приложения отключено кодом. Для SLF4J 2 не добавляется устаревшее подавление `StaticLoggerBinder` из SLF4J 1.x. |

Дополнительных правил приложения сейчас не требуется: файл `rules.keep` фиксирует
состав и обоснования, а сами vendor rules автоматически входят в R8 configuration.
Глобальные `-dontwarn **`, `-ignorewarnings`, `-keep class **` и отключение
оптимизации не используются. Ошибки missing classes должны останавливать сборку.

## Проверка и диагностика

Собрать подписанный APK и запустить `lintRelease` по [инструкции выпуска](RELEASING.md).
До тега используется `-PcandidateReleaseTag=v1.0.0`.

Результаты R8 находятся в `app/build/outputs/mapping/release/`:

- `configuration.txt` — итоговые правила с источниками;
- `mapping.txt` — соответствие имён для retrace;
- `usage.txt`, `seeds.txt`, `resources.txt` — удалённый код, сохранённые entry points и ресурсы.

Архивировать `mapping.txt` вместе с каждым опубликованным APK: mapping от другой
сборки нельзя использовать для надёжного восстановления stack trace.

JVM-тесты не запускают обфусцированный DEX. На **подписанном минифицированном APK**
перед выпуском дополнительно проверить:

1. Холодный запуск, загрузку списка городов и поиск: Koin, Orbit, coroutines,
   Ktor/OkHttp и JSON-десериализация.
2. Открытие города, возврат, переключение вкладок: сериализаторы navigation routes.
3. Загрузку карты, подписей и пинов, открытие карточки пина: MapLibre JNI и GeoJSON/Gson.
4. Возврат из фона и восстановление экрана после пересоздания процесса.

При ошибке исследовать конкретную рефлексию/JNI и `configuration.txt`; добавлять
узкое правило только для подтверждённого entry point. После обновления зависимостей
повторять release-сборку и эти сценарии.
