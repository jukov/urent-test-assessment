# Repository guidelines

Проектная документация хранится в каталоге `./docs`.

## Процесс разработки

- Каждая задача, требующая реализации, выполняется в отдельном Git worktree.
- При изменении логики добавляются или обновляются тесты затронутого поведения: unit-тесты для отдельных компонентов, интеграционные — для взаимодействий. Новый тест не обязателен для каждой задачи, если изменение не затрагивает поведение или оно уже покрыто подходящими тестами. Для изменений только в документации тесты не требуются.
- Тесты должны проверять логику, наблюдаемое поведение и значимые контракты. Не добавляются формальные проверки значений констант, прямых присваиваний или копии реализации без самостоятельного ожидаемого результата. Значения проверяются через поведение, которое от них зависит, когда это важно для требований.
- README предназначен для клиента, пользователя и ревьюера тестового задания: описание приложения, запуск, проверка, существенные решения и ограничения. Он не является журналом задач и не обновляется автоматически после каждой правки. README меняется только тогда, когда меняется полезная этим читателям информация; ход работы и результаты проверок описываются в задаче или PR.
- После реализации каждой продуктовой или инженерной задачи, включая задачи по CI, необходимо запустить отдельного Codex-агента для независимого ревью изменений.
- После независимого ревью необходимо устранить найденные замечания до завершения задачи.
- Если ревью пройдено успешно, создается PR в main ветку на Github.
